# Vault stewardship

Stewardship keeps an Empire usable as work, evidence and decisions accumulate.
It is a capability of `legends-empire`, reached through `cto-legends`. It needs
no separate skill, service, database or project-management subscription.

Start with the user's outcome:

| Request | Work to perform |
| --- | --- |
| Clean and organize this vault | Inventory, inspect high-impact findings, propose a bounded repair campaign, verify the result |
| Review neglected projects | Read project outcomes and current evidence; resolve missing owners, blockers and next actions |
| Help me resume this work | Read the session handoff, verify evidence and restore a concrete next action |
| Put this knowledge in its right place | Use the user's ontology; link from the relevant entry point and preserve source provenance |
| Keep my Empire healthy | Review the previous campaign, compare a fresh inventory, and choose the next useful improvement |

Read [the operating playbook](playbook.md), [the ontology](ontology.md),
[record templates](records.md), and [verification standards](verification.md).

These files are shipped references. Personal campaigns and project records
belong in the user's vault, outside this reference directory. The attachment
entry point and `work/` space are user owned. The module's installed
`docs/stewardship.md` remains the command reference for its exact version.

## What earns this capability its place

An agent supplies interpretation. Stewardship supplies the repeatable checks,
source hashes, bounded review queue, record contracts and before/after proof
that make the interpretation accountable and resumable across agents.
A clean report alone is not success. Success is more reliable navigation,
accurate project state and a trustworthy next action, with evidence preserved.
